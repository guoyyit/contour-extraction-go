# contour-extraction-go

本地可运行的规则格网标量数据等值线（contour）提取服务。输入为本地生成或
本地文件读取的规则格网，输出按指定级别提取的折线；支持分块并行、块间无缝
拼接、拓扑保持简化、退化输入的显式语义，以及确定性与增量级别复现。整个服务
不依赖任何外部服务。

## 算法概要

- 每个规则单元（cell）沿固定的 **左上–右下对角线** 切成两个三角形，
  对每个三角片做 marching triangles（线性插值）。固定对角线消除了经典
  marching squares 的鞍部（saddle）二义性：任意数据的连接方式都唯一确定。
- 每条线段都完全位于一个三角片内部，三角片互不重叠，因此线与线在几何上
  不可能交叉；鞍部由多条分别闭合/开放的线表达。
- 线段端点带有结构化的全局身份键 `endKey`：横边、竖边、单元对角线或格点。
  只有共享同一条边的三角片才产生相同键，因此分块边界处天然无缝，
  与分块大小、worker 数、调度顺序无关。

## 连接规则

拼接（`stitch`）严格按端点键进行：

1. 键相同的两个线段端点必须相连。
2. 一个内部键上恰有两条入射边时直接相连。
3. 一个内部键上有 3 条及以上入射边（只可能出现在取值恰为级别的格点等
   退化情形）时，按各边离开该点的极角升序排列，配对相邻方向
   `(0-1),(2-3),...`；方向相同的极端情况以另一端键作为确定性次序。
   该配对唯一、确定，不依赖任何处理顺序。
4. 落在格网外边界、以及已定义/未定义交界（barrier）上的键不做配对，
   每条入射边都是一条开放等值线的端点。
5. 因此每条输出折线要么闭合，要么两个端点都位于数据外边界或未定义区
   边界，不存在内部悬挂线段。
6. 所有折线按规范形式输出（闭合环以字典序最小点为起点并选择字典序较小
   的遍历方向；开放线首点字典序不大于末点；集合整体排序），相同输入
   永远逐位一致。

## 取值恰为等值级别的格点

`exact-level` 有两种可配置语义：

- `perturb`（默认）：使用**字典序无穷小扰动**
  `f'(r,c) = f(r,c) + ε·c + ε²·r`，其中 `0 < ε² ≪ ε` 小于任意两个不同
  浮点值之差。扰动是纯符号计算，不修改输入、不改变任何非平局分类。
  数学上保证任意格点都不恰好落在级别上，等值线在每个三角片内是完整的
  一段直线，连接关系由坐标唯一决定，无断点、无孤立点。
  几何穿越点仍按原始值线性插值计算：取值恰为级别的格点会作为穿越点
  落在相邻格边/对角线上。
- `strict`：严格按上水平集 `{f > level}` 处理，恰为级别的格点归入
  “非上侧”。该语义在边界上更严格，但可能使等值线在恰为级别的格点处
  终止（明确、可复现）。

零维退化（单个孤立格点恰为级别、其邻域全部严格低于级别）不产生线段：
单点既不形成闭合环也不形成悬线，两种语义一致。

## 平坦区域

`flat` 配置：

- `suppress`（默认）：四个角点全部恰为级别的单元内不生成线段，
  避免在平坦高原（plateau）内部产生之字形伪闭合。高原边界上的线段
  仍然保留，并成为止于高原边界的开放折线，不产生伪闭合环。
- `draw`：按 `perturb` 的符号决胜在平坦区域内部也生成确定性连接线。
  高原内部会出现沿格点行进的之字形等值线，仅在确有该可视化需求时使用。

整片区域取值为同一常数且不等于级别时，任何配置下都不产生线段。

## 未定义值语义

NaN 格点表示未定义。`undefined` 目前唯一支持的策略为 `barrier`：

- 未定义格点视为屏障；包含 2 个或 3 个未定义角点的三角片不产生线段。
- 恰含 1 个未定义角点的三角片，只有当两个已定义角点取值分列级别两侧
  时才生成一条线段：从两已定义角点之间的真实穿越点连到
  “未定义角点 ↔ 上侧已定义角点”边的中点（该中点带 `barrier` 键）。
- 因此等值线明确止于已定义/未定义交界处，绝不穿入未定义区域，也不会
  沿未定义区域凭空造出闭合环。这种终止于未定义区边界的折线在简化时
  原样保留（终止段位于无插值定义的三角片内）。

## 分块并行

- 分块是单元矩形的一个互不重叠的划分；块边界上的格边由唯一的单元
  三角片产生穿越点，所以不需要重叠区（halo）。
- 每个 worker 独立处理分块，线段写入各自的分片缓冲，无共享写、无锁竞争。
- 全部缓冲按分块的规范顺序合并后做一次全局拼接；输出与单块提取
  （`ExtractLevel`）逐点一致（测试 `TestTileEquivalence` 覆盖多种
  分块大小与并发度组合）。
- 分块工作内存只与单块大小相关、不随总格网增大而增长
  （`TestBoundedTileMemory`），吞吐随并发度提升
  （`TestScalingWithConcurrency` 与基准 `BenchmarkExtractTiled`）。

## 拓扑保持简化

`simplify.enabled` + `simplify.tolerance`（格网坐标单位）启用
Douglas–Peucker 简化。每条候选弦只有通过全部检查才会被采用，否则
退化为保留原始段：

1. 不与同级别其他等值线的原始边横交（无线间交叉）。
2. 沿弦每 0.2 个格距用与提取相同的固定对角三角定义域做采样
   （完全定义单元用双线性插值，部分未定义单元只在完全定义三角片内
   插值），样本不得明显翻到等值线另一侧
   （数值裕量为 `1.5 × tolerance`），也不得进入未定义三角片。
3. 弦只在 DP 递归中替换同一条折线的相邻子链，配合上面两条保证不自交。

简化只会“拉直”等值线，不改变其分隔的取值区域：不会产生自交、
线间交叉或穿越异值区域。

## 确定性与增量级别

- 所有排序（级别、分块、端点配对、折线规范化）都是确定性的；
  合成数据使用固定种子的 LCG，跨机器/跨运行一致。
- `Service` 按级别独立提取并缓存。`AddLevels` 只计算之前不存在的级别，
  已缓存级别永不重算；新级别结果与一次性全量提取一致，且追加级别后
  原级别结果保持不变（`TestIncrementalEqualsBatch`）。
- `Snapshot` 给出可序列化结果，可写成本地 JSON，用于复现历史结果。

## 配置项

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `Levels` | — | 等值级别；内部自动去重升序 |
| `Concurrency` | `0` | 分块 worker 数，`0`=CPU 数 |
| `TileCells` | `0` | 分块单元边长，`0`=自动（约 256） |
| `Undefined` | `barrier` | 未定义值语义（目前唯一） |
| `ExactLevel` | `perturb` | 恰为级别格点：`perturb`/`strict` |
| `Flat` | `suppress` | 平坦级别单元：`suppress`/`draw` |
| `Simplify.Enabled` | `false` | 是否启用拓扑保持简化 |
| `Simplify.Tolerance` | `0` | 简化容差（格距单位），须 ≥ 0 |

## 命令行用法

```sh
# 本地生成数据并提取，文本摘要输出到 stdout
go run ./cmd/contour -rows 200 -cols 200 -kind gaussian -seed 3 \
  -levels 0.5,1.5,2.5 -workers 4 -simplify-tol 0.4

# 读本地格网文件，结果写 JSON
go run ./cmd/contour -in grid.txt -levels 0,1,2 -out contours.json

# 生成数据的同时把格网写盘，便于离线复现
go run ./cmd/contour -rows 80 -cols 80 -write-grid grid.txt -levels 1
```

格网文本格式：

```
rows cols
v00 v01 ... v0(cols-1)
...
```

数值为浮点文本，`nan`（大小写不敏感）表示未定义格点。

## 测试与基准

```sh
go test ./...                 # 全部测试（退化输入/拼接/简化/增量/确定性）
go test -short ./...          # 跳过耗时的扩展/内存测试
go test -bench .              # 分块并行基准
CONTOUR_CHECK_SCALE=1 go test -run Scaling -v  # 并行加速比验证
```

## 主要 API

- `NewGrid`、`GenerateGrid`、`ReadGridFile`：构造/生成/读取格网。
- `ExtractLevel(g, level, cfg)`：单块提取（参照实现）。
- `ExtractLevelTiled(g, level, cfg)`：分块并行提取，返回结果与统计。
- `NewService(g, cfg)`、`AddLevels`、`All`、`Snapshot`：增量、确定性服务。
